# Swift版 コマンド互換性チェックリスト(ゴールデンテスト用ドラフト)

元ネタ: [command-spec-ex.md](command-spec-ex.md)(`ex.1`/`TODO`/`Changes`由来)、
[command-spec-vi.md](command-spec-vi.md)(`vi.1`由来)。アーキテクチャの詳細は
[ex-mode.md](ex-mode.md)/[vi-mode.md](vi-mode.md)/[regex.md](regex.md)を参照。

## 使い方

このチェックリストは`ExCoreTests`のゴールデンテスト計画のドラフトです。大分類ごとに
「その分類の全項目にテストがある」ことを示すチェックボックスと、**仕様上とくに間違えやすい・
テストで明示的に固定すべき挙動**を個別項目として挙げています。単純な一覧の網羅性は
`command-spec-ex.md`/`command-spec-vi.md`側に既にあるため、ここでは重複を避け「テスト設計上
注意すべき点」に絞っています。実装時は各分類について、該当ファイルの一覧を上から順に
1コマンド最低1ゴールデンテスト、を原則とします。

---

## A. exコマンド

- [ ] `command-spec-ex.md`§1の全コマンド(約60種)に最低1ゴールデンテストがある
- [ ] コマンド名の前方一致による省略解決(曖昧な場合はより一般的なコマンドが優先)を検証するテスト
- [ ] `!`変種(`a!`, `c!`, `e!`, `g!`/`v`, `n!`, `q!`, `rew!`, `w!`, `wq!`)が非変種と異なる挙動を
  持つことを個別に検証
- [ ] `read !command`と`w !command`(いずれも`!`を含むが`read`/`write`本体とは別構文)を、単純な
  `:!command`(シェル実行)や`addr,addr!command`(フィルタ)と混同しないテスト
- [ ] `&`(直前のsubstitute繰り返し)と`~`(直前の正規表現+直前の置換パターンで繰り返し)の違いを
  区別するテスト
- [ ] `z`コマンドの型(無指定/`z=`/`z^`/`.`/`-`)ごとの表示行の違い

## B. アドレス指定構文

- [ ] `.`, `n`, `$`, `%`, `+n`/`-n`, `/pat/`, `?pat?`, `''`, `'x` 各構文の単体テスト
  (`command-spec-ex.md`§2)
- [ ] `,`区切りと`;`区切りの違い(`;`は左側評価後に`.`を更新してから右側を評価する)
- [ ] 2アドレス指定で1つ目が2つ目より後の行の場合にエラーになること
- [ ] アドレスを受け付けないコマンドにアドレスを与えた場合にエラーになること
- [ ] `/pat/`省略時(直前の正規表現を使う)、`\/`・`\?`(走査用正規表現を使う、置換直後は`//`・`??`が
  置換用正規表現を使う点に注意)の区別

## C. `:set` オプション

- [ ] `command-spec-ex.md`§3の全オプションについて、Boolean/文字列/数値それぞれの構文
  (`set opt`/`set noopt`/`set opt=val`/`set opt?`)が動作する
- [ ] `edcompatible`が`substitute`の`g`/`c`サフィックスの記憶・トグル挙動を変えることの確認
  (Swift版で`ed`互換モードをどこまでサポートするかは実装時に要判断)
- [ ] `magic`/`nomagic`で正規表現メタ文字の扱いが変わることの確認
- [ ] 端末チューニング系オプション(`hardtabs`, `optimize`, `redraw`, `slowopen`, `w300`/`w1200`/
  `w9600`等)はSwift版のターミナル層(`ncurses`)では**意味が消滅する候補**——実装しない場合は
  「意図的に非対応」として明示的に文書化する(未対応を隠さない)

## D. 正規表現・置換パターン

- [ ] `magic`基本構文(`^ $ . [ ] \( \) * \{m,n\} ~ \n`)の各要素のゴールデンテスト
  (`command-spec-ex.md`§5)
- [ ] `nomagic`時にメタ文字が`^`/`$`のみに縮小することの確認
- [ ] 置換パターンのメタ文字(`& ~ # \n \u \l \U \L...\E/\e`)の各ゴールデンテスト
- [ ] Swift `Regex`との**意図的な非互換**を許容する項目の一覧化: 伝統的`\(...\)`グルーピングと
  `\<`/`\>`単語境界の挙動差異(`swift-vi-research-notes.md`§2「正規表現」で許容済み)
- [ ] `LC_COLLATE`無視(`[.c.]`/`[=c=]`が単一文字として扱われ実質無意味、範囲表現は常にバイト順)は
  **原典のバグではなく既知の制約**(`TODO`/`docs/regex.md`のstubs.c分析と一致)なので、Swift版でも
  同様の制約でよいか、あるいはSwift Regexのロケール対応をそのまま使い原典より賢くしてよいかを
  明示的に決定する項目として残す

## E. Changesベースの「意図的に踏襲する仕様」(POSIX確定挙動)

`command-spec-ex.md`§7で分類済みの「POSIX準拠のための挙動変更」は、Swift版でもそのまま踏襲すべき
確定仕様とみなす。個別ゴールデンテスト化する項目:

- [ ] RE区間表現`\{m,n\}`・後方参照`\1`〜`\9`が動作する
- [ ] 置換パターンが`%`単独の場合、直前置換のパターンを使う
- [ ] `substitute`が`sub`/`subst`等に省略可能
- [ ] `ignorecase`トグル時に保存済み正規表現も追従する
- [ ] 存在しないファイル名を`edit`した場合、成功して`[New file]`と表示する
- [ ] `next!`実行時、`autowrite`設定時でもカレントファイルを書き込まない
- [ ] ファイルを開けない/無効アドレス/タグ未検出の場合、非0の終了ステータスを返す
- [ ] `-t`と`-c`両方指定時は`-t`(タグ位置)を先に処理する
- [ ] `undo`操作で変更された行のマークが保持される
- [ ] visualモードの`X`が(誤って`x`と同じにならず)正しく「カーソル前の文字を削除」する

**意図的に再現しない項目**(移植環境固有の修正、Swift版では前提が異なる):
- [ ] `NO_BE_BACKSLASH`まわりのブラケット式内バックスラッシュ挙動切り替えは、Swift版の正規表現
  方針(Swift `Regex`使用)次第で不要になる可能性が高い——実装時に要否を再判断
- [ ] マルチバイト関連の個別バグ修正群(EUC-JP/Big5の`r`コマンド不具合、複数カラム文字の画面描画等)
  はSwift版の内部`String`統一により構造的に発生しない想定——発生しないことの確認テストに置き換える

## F. viモーション

- [ ] `command-spec-vi.md`§1の全モーション(文字/単語/行・画面/文・段落・セクション/文字検索/
  マーク)に最低1ゴールデンテスト
- [ ] カウント前置(`3w`, `5j`等)の一般規則の確認
- [ ] `f`/`F`/`t`/`T`と`;`/`,`(直前検索の繰り返し・逆方向繰り返し)の組み合わせ
- [ ] 単語(`w`/`b`/`e`)と WORD(`W`/`B`/`E`、空白区切り)の違いを明確に区別するテスト

## G. viオペレータ+モーションの組み合わせ

- [ ] `command-spec-vi.md`§2の全オペレータ(`d c y < > ! =`)について、行全体対象(`dd`等の
  2重指定)と部分対象(`dw`等)の両方をテスト
- [ ] カウントの伝播規則: オペレータ側/モーション側どちらに付けても等価(`3dw` == `d3w`)である
  ことの確認。`!`のみ例外(`!!`+前置カウントは行数指定)であることも確認
- [ ] 1行の一部だけが対象の場合、変更前の最後の文字位置に`$`が表示されること(`c`/`s`)

## H. vi挿入コマンド

- [ ] `command-spec-vi.md`§3の全コマンド(`i a I A o O R s S C r`)の違いを個別にテスト
- [ ] 挿入中の特殊操作(`^H ^W ^T ^D ^V/^Q ^@`)の個別テスト

## I. マーク・レジスタ

- [ ] マーク`a`-`z`の設定・参照(`` ` ``=文字位置、`'`=行全体)の違い
- [ ] 番号付きバッファ`1`-`9`(削除内容の自動退避、直近ほど若い番号)の遷移ルール
- [ ] 名前付きバッファ`a`-`z`への明示的ヤンク/デリート/ペーストの往復

## J. 繰り返し・アンドゥ

- [ ] `.`(リピート)が「直前にバッファを変更したコマンド」を対象にすること(単なるキーストローク
  再生ではない)、カウント上書き(`2dw`の後`3.`で3語削除)の挙動
- [ ] `u`の交互切り替え(連続実行で2状態をトグル)
- [ ] `U`(行全体の巻き戻し)と`u`の違い

## K. 画面制御・モード切替

- [ ] `command-spec-vi.md`§7/§8の各キーは自動ゴールデンテスト化しづらいため、実機/手動確認の
  チェック項目として別途`run`スキル等での動作確認に回す(フェーズ7「主要コマンドの一通りの
  動作確認」で扱う)

## L. 既知の制限(意図的に残すか要判断)

`command-spec-vi.md`§9末尾の既知の制限:
- [ ] `:source`をvisualモード中の`:`から呼んだ場合の`:append`/`:change`/`:insert`不可制約
- [ ] `wrapmargin`が長い単語でだまされる(折り返されないことがある)仕様

これらはSwift版で無理に解消せず「既知の制限」として明示ドキュメント化するか、Swift版では
構造的に解消されるかを実装時に個別判断する。
