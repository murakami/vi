# vi ビジュアル(スクリーン編集)モード

対象範囲: `ex_v.c`, `ex_vmain.c`, `ex_vget.c`, `ex_voper.c`, `ex_vops.c`/`ex_vops2.c`/`ex_vops3.c`,
`ex_vput.c`, `ex_vadj.c`, `ex_vwind.c`, `ex_vis.h`, `ex_tty.c`/`ex_tty.h`。

exモードコア(コマンドディスパッチ/バッファ/アドレッシング)、正規表現、端末層(termcap)、
リカバリ&メモリは別文書を参照。

## 1. exモードからviモードへの遷移とメインループ構造

viには実は4つの内部状態があり、`ex_vis.h` の `bastate`/`state` (`VISUAL` / `CRTOPEN` /
`ONEOPEN` / `HARDOPEN`) で管理される。端末の能力(アドレス指定可能なカーソル移動 `CA`、
上移動 `UP`、画面クリア `CL`、スクロール `SF` など、termcap由来のケーパビリティフラグ)に
応じて `vop()` (`ex_v.c:257`) が実際に使う状態を決める。カーソルアドレッシングができない
端末では `vop()` は自分では動作せず `oop()`(open mode、1行編集寄りの縮退モード)へフォール
バックする。

エントリーの流れ(`vop()` / `oop()`、`ex_v.c`):
1. `ovbeg()` で現在の対象行を確定し、`fixzero()` で空バッファ状態を補正。
2. `bastate` を決定し、`setwind()` でウィンドウサイズ(`WTOP`/`WLINES`/`WCOLS`等 `ex_vis.h`)を計算。
3. `Outchar = vputchar` で出力関数を画面用に切り替え(通常のex出力 `termchar` から差し替え)。
4. `f = ostart()` (`ex_put.c`) で端末をrawモードに切り替え、戻り値 `f` に元の `termios` を保存。
5. `vmain()` (`ex_vmain.c`) がメインループとして走り、Q/ZZ などで抜けるまで戻らない。
6. `ovend(f)` (`ex_v.c:236`) で `ostop(f)` により端末モードを元に戻し、エコー領域をクリア。

`vmain()` (`ex_vmain.c:97`) は無限 `for(;;)` ループで、1キー入力あたり概ね次のサイクルを回す:

1. `TSYNC()` で一時ファイル(編集バッファ)を必要なら同期。
2. カウント(`3dw` の `3` のような数値プレフィクス)と `"a` のような名前付きレジスタ指定を
   `peekkey()`/`getkey()` でgobbleする(`looptop:` ラベルのループ)。
3. `op = getkey()` で実コマンド文字を取得し、`map()` でキーマッピング(`:map` によるユーザー
   定義マッピングや矢印キー変換)を(`REMAP`オプションが立っていれば)最大256回まで再帰的に適用。
4. `lastcp`/`workcmd` へ入力中のコマンド文字列を記録していく(`.` によるリピート実行のため)。
5. 巨大な `switch (c)` で「1文字で完結するコマンド」(`^L`, `.`, `@`, `J`, `O`/`o`, `A`/`a`/`i`/`I`/`R`,
   `m`, `Y`, `S`, `~`, `u`, `U`, `p`/`P`, `ZZ`, `:`, `^Z`, `^]`, `&`, `^^`, `^F`/`^B`/`^D`/`^U`/`^E`/`^Y`
   などスクロール系)をここで直接処理して `continue`。
6. それ以外(オペレータ+モーションの組み合わせが必要なコマンド、および単純な移動コマンド)は
   `operate(c, cnt)` (`ex_voper.c`) に委譲する。

`:` コマンドはvi内から `commands(1, 1)` (ex_cmdsub.c 側、exモードのコマンドディスパッチ)を
直接呼び出すことでex行コマンドをその場で実行しており、ex本体とvi本体は同じプロセス内で
完全にコード共有されている(`doinit:` ラベル以降のブロック)。`^]` (タグジャンプ)や `^^`
(前のファイルに戻る)、`&`(直前の置換の繰り返し)なども、対応するex `:`コマンド文字列
(`"tag"`, `"e #"`, `"&"` など)を `globp` に仕込んで `commands()` を呼ぶ、という同じ仕組みで
実装されている。

## 2. モーションとオペレータの組み合わせ (`operate()`, `ex_voper.c`)

viの `d`/`c`/`y`/`!`/`<`/`>`/`=` はいずれも「オペレータ」で、後続の1文字(または`f`/`t`/`'`などの
複合)で指定される「モーション」と組み合わさって初めて範囲が確定する、という2段階デコードに
なっている。すべて `operate(int c, int cnt)` (`ex_voper.c:117`) 一箇所で処理される。

流れ:
1. 先頭の `switch (c)` でオペレータ文字かどうかを判定。オペレータであれば `moveop`/`deleteop`
   という関数ポインタを対応する実装(`vdelete`, `vchange`, `vyankit`, `vfilter`, `vshftop`。
   すべて `ex_vops*.c`)に設定し、`goto nocount` せず追加のカウント・モーション文字を読み込む。
   オペレータでない場合(`b`/`w`/`e`/`0`/`$`/`G`/`/`/`?`/`'`/`` ` ``/`H`/`M`/`L`/`j`/`k` などの
   単純移動)は `moveop = vmove` のまま `nocount:` に飛ぶ。
2. 2番目の巨大 `switch (c)` (モーション文字の switch) で `wcursor`(行内の終端位置。0なら
   「相手行の非空白先頭」を意味する)と `wdot`(行単位の終端行。`NOLINE`なら「現在行」を意味する)
   を設定する。例えば `w`/`b`/`e` は `llfind()` で単語境界を探索して `wcursor` を更新し、
   `j`/`k`/`+`/`-`/`G`/`H`/`M`/`L` は行番号を計算して `wdot` を更新する。`/`, `?` はその場で
   `readecho()` + `address()` により検索パターンを評価し、マッチ位置を `wcursor`/`wdot` に反映する。
3. 最後に `(*opf)(c)` (`ex_voper.c:806`、`opf` は `moveop` と同一)を呼び、`wcursor`/`wdot`
   (=`cursor`/`dot` とであわせて確定した範囲)に対して実際の削除・変更・ヤンク・フィルタ・
   シフトを実行する。単純移動の場合は `opf == vmove` であり、範囲確定後にカーソルを移すだけ。

この「モーション決定とオペレータ適用の分離」により、`dw`(単語削除)・`cw`(単語変更)・
`yw`(単語ヤンク)・`>j`(2行シフト)のような全組み合わせを、モーション側のコード重複なしに
実現している。`3dw` のような数値は `operate()` 冒頭でオペレータのカウントとモーションの
カウントが掛け合わされる(`cnt *= vgetcnt()`)。

## 3. 画面再描画: フル再描画と差分更新

画面上の各行の状態は `ex_vis.h` の `struct vlinfo vlinfo[TUBELINES + 2]` (`vliny`=Y座標,
`vdepth`=表示行数, `vflags`=`VDIRT`ビットで「汚れている」か)として保持され、
`vtube[]`/`vtube0` (`ex_vis.h`)には実際の端末画面の内容そのもののコピー(スクリーン
イメージ)がミラーリングされている。これにより「今何が画面に出ているか」をメモリ上で
正確に把握し、無駄な再描画を避ける。`TUBELINES`/`TUBECOLS`(`config.h`)がこのミラー
バッファの最大サイズ上限であり、大きな端末を使うにはこれらを増やす必要がある
(READMEにも記載あり)。

再描画には2段階ある(いずれも `ex_vadj.c`):

- **`vsync(p)`** (保守的・軽量): 画面の一部分だけを、必要な行の `VDIRT` フラグを見ながら
  最小限更新する。低速回線やdumb端末向けの経路。
- **`vredraw(p)`** (`ex_vadj.c:679`、積極的・網羅的): 指定行 `p` から画面全体を、`@`行
  (画面には収まらない行のプレースホルダ)を出さずにできる限りきれいに埋め直す。行削除・
  挿入の際は端末のDL(delete line)/AL(insert line)ケーパビリティ(`vdellin`,`vinslin`、
  `ex_vadj.c`)があればそれを使い、なければ「その行を`VDIRT`とマークするだけ」に留めて
  次の同期時にまとめて描画する、というグレースフルデグラデーションになっている。
- **`vrepaint(curs)`** (`ex_vadj.c:588`) が上記2つを状況(現在行が画面内かどうか、画面が
  空かどうか)に応じて使い分ける、実質的なエントリポイント。`vmain()`のコマンド処理後や
  `ex_vops*.c`の各操作末尾から頻繁に呼ばれる。

`vputchar()`/`physdc()` (`ex_vput.c`) が実際の文字出力と、カーソル位置・表示済み内容との
差分検出(同じ内容ならエスケープシーケンスを送らない)を担当し、`vgoto()` (`ex_vput.c:363`)
がカーソル移動そのものを、絶対移動用エスケープと相対移動(方向キー相当のtermcap `nd`/`up`/`do`
等)のコスト比較で最適な方を選ぶ(古典viの「カーソル移動コスト計算」ロジック)。

## 4. ウィンドウ調整とスクロール (`ex_vadj.c` / `ex_vwind.c`)

役割はおおむね次のように分かれている:

- **`ex_vwind.c`**: 「現在行(`dot`)を画面のどこに持ってくるか」という高レベルの方針を扱う。
  `vjumpto()`/`vmoveto()` (画面外への大きな移動、コンテキスト再構築を伴う)、
  `vup()`/`vdown()` (`^U`/`^D`/`^F`/`^B`のような画面単位のスクロール、カーソルの同一列維持)、
  `vupdown()` (行送りの共通処理)、`vcontext()` (指定行を画面のどの位置(先頭/中央/末尾等)
  に置くかの計算)、`vclean()` (画面情報を捨てて汚れなしの状態に戻す)。
- **`ex_vadj.c`**: 上記の方針を実際の画面操作(行の物理的な挿入/削除、スクロールバッファ
  操作)に落とし込む低レベル層。`vscroll()`, `vrollup()`, `vopen()`/`vreopen()` (1行を開いて
  表示domain作る)、`vinslin()`/`vdellin()` (物理行の挿抜、termcap `AL`/`DL`利用)、
  `vreplace()` (置換系操作後にvlinfoを再構築)。

この分離により、「スクロールしたい」という意図(vwind)と「実際に端末へどう指示するか」
という実装(vadj)が分けられ、`ex_vadj.c`側だけを見れば端末機能の有無に応じた
フォールバック戦略が追える。

## 5. raw ttyモードの設定・解除

- `ostart()` / `ostop()` (**`ex_put.c`**、vi専用ファイルではないが vi の出入りに必須) が
  raw/cooked切り替えの実体。`ostart()` は `gTTY(1)` で現在の `termios` を取得し、
  `ICANON`/`ECHO`を落とし `VMIN=1`/`VTIME=1` に設定した上で `sTTY(1)` により適用、
  戻り値として「呼び出し前の`termios`」を返す。呼び出し側(`ex_v.c`の`vop()`/`oop()`)は
  これを `f` に保持しておき、`vmain()` から戻った直後に `ostop(f)` へ渡して元に戻す。
- `vop()` (`ex_v.c:257`) はエントリ時に `resize = SETJMP(venv)` を張っており、
  `SIGWINCH`(端末リサイズ)ハンドラ `onwinch` がこの `venv` へ `longjmp` することで
  ウィンドウサイズ変更時にサイズ再計算(`setsize()`)へ復帰できるようになっている。
  `signal(SIGWINCH, onwinch)` はvi突入時に張り、`ovend()`の後で `SIG_DFL` に戻す。
- `^Z`(サスペンド、`SIGTSTP`環境のみ)は `vmain()` 内の `case CTRL('z')`
  (`ex_vmain.c`)で特別扱いされておらず、`globp = "stop"` として ex側の `stop` コマンド
  文字列を仕込み `doinit:` 経由で `commands()` に投げているだけである。つまりrawモードの
  一時解除・サスペンド後の復帰処理そのものは ex コマンド `stop` の実装側
  (`ex_cmds2.c`、`ostop`/`tostart`/`tostop`呼び出し)に委ねられている。外部コマンド実行
  (`:!` や `!`オペレータ)でも同様に、一時的にcookedモードへ戻してからコマンドを実行し、
  戻ってきたら再度rawモードへ、という往復が発生する。

## 6. 主要コマンドの実装場所

| コマンド | 概要 | 実装 |
|---|---|---|
| `i` / `a` / `I` / `A` / `R` | 挿入モード開始(各種バリエーションは `cursor` 位置調整後 `insrt:` に合流) | `vmain()` の `case 'i'`/`'a'`/... → `vappend()` (`ex_vops2.c:257`) |
| `o` / `O` | 新規行を開いて挿入 | `voOpen()` (`ex_vops.c:719`) |
| `d`/`c`/`y`/`!`/`<`/`>` + モーション | オペレータ+モーション | `operate()` (`ex_voper.c:117`) → `vdelete`/`vchange`/`vyankit`/`vfilter`/`vshftop` (`ex_vops*.c`) |
| `/` `?` (検索、モーションとしても単体コマンドとしても) | 正規表現検索 | `operate()` 内 `case '/': case '?':` → `address()`(`ex_addr.c`側)呼び出し |
| `.` | 直前の変更コマンドをリピート | `vmain()` の `case '.'`: `lastcmd`/`lastcnt`/`lastreg` を使い `vglobp = lastcmd` として `reread` へ |
| `u` | 直前の変更を取り消し | `vundo()` (`ex_vops.c:139`) |
| `U` | 現在行を編集開始時点の状態へ復元 | `vUndo()` (`ex_vops.c:112`) |
| `p` / `P` | レジスタ/直前削除内容のプット | `vmain()` の `case 'p': case 'P':` → `put`/`putreg` (レジスタ実装はexモード側) |
| `~` | カーソル位置の大文字/小文字切替 | `vswitch()` (`ex_vops*.c`) |
| `m` / `'` / `` ` `` | マーク設定/参照 | `vmain()` の `case 'm':` (設定) と `operate()` の `case '\'': case '\`':` (参照、`markreg`/`getmark`) |
| `ZZ` / `Q` | 保存終了/exモードへ抜ける | `vmain()` の `case 'Z':`(`globp="x"`経由)、`case 'Q':` |

いずれのコマンドも、実行後は最終的に `vrepaint()`/`vnline()` (`ex_vadj.c`/`ex_vwind.c`) を
呼んで画面を確定状態に同期させてから `vmain()` のループ先頭に戻る、という共通の後始末
パターンに従っている。
