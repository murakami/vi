**コマンド構文の一般規則**:
- コマンド名は英単語の先頭一致で省略可能(曖昧な場合はより一般的なコマンドが優先される)
- ほとんどのコマンドはアドレス範囲を前置でき、末尾に`count`(行数)を取れるものもある
- コマンド名直後の`!`はコマンドの「変種」を意味する(デフォルト動作をオプションでトグルする場合もある)
- コマンド末尾の`#`(行番号表示)・`p`・`l`フラグ(`p`/`l`は空白/タブ前置が必要、例外は`dp`)で
  コマンド完了後に追加の表示コマンドを実行できる。`+`/`-`を繰り返すことでオフセット表示も可能
- `"`で始まる行はコメントとして無視される。コマンド末尾にも`"`でコメント可能(シェルエスケープと
  `substitute`/`map`を除く)
- `|`で複数コマンドを1行に連結可能(ただし`global`・コメント・シェルエスケープ`!`は`|`で終端できない=
  行の最後でなければならない)

## 2. アドレス指定構文

| 構文 | 意味 |
|---|---|
| `.` | カレント行 |
| `n` | バッファのn行目(1始まり) |
| `$` | 最終行 |
| `%` | `1,$`の省略形(バッファ全体) |
| `+n` / `-n` | カレント行からの相対オフセット(`.+3`, `+3`, `+++`は同値) |
| `/pat/` / `?pat?` | 前方/後方への正規表現検索(バッファ端で折り返す)。末尾の区切り文字は省略可。
  `pat`省略時は直前の正規表現を使用。`\/`・`\?`は直前の走査用正規表現を使う(置換直後は`//`・`??`が
  置換用正規表現を使う点に注意) |
| `''` | 直前の非相対移動前のカレント行位置(自動マーク) |
| `'x` | `mark`コマンドで設定したマーク`x`の行 |

- アドレスは`,`または`;`で区切って複数指定できる(左から順に評価)。`;`区切りの場合、直前の
  アドレス式の評価後にカレント行`.`がその値に更新されてから次のアドレスが解釈される
- 2アドレスを取るコマンドでは、1つ目のアドレスが2つ目より前の行でなければならない
- アドレス省略時のデフォルトはカレント行(`,100`は`.,100`と同義)
- アドレスを受け付けないコマンドにアドレスを与えるとエラー

## 4. コマンドライン引数・起動オプション

```
ex [-c command|+command] [-r [filename]] [-s|-] [-t tagstring] [-w size] [-lLRvV] [file ...]
edit [-c command|+command] [-r [filename]] [-s|-] [-t tagstring] [-w size] [-lLRvV] [file ...]
```

| オプション | 意味 |
|---|---|
| `-c command` / `+command` | 編集開始時に指定コマンドを実行 |
| `-l` | Lisp用の特殊モードで開始 |
| `-r [filename]` | 引数なし: 復旧可能なファイル一覧を表示して終了。`filename`指定: 該当一時ファイルを復旧モードで開く |
| `-L` | `-r`(引数なし)と同義 |
| `-R` | 読み取り専用で開く |
| `-s` / `-` | スクリプトモード。対話フィードバック無効化、`EXINIT`/`.exrc`を処理しない |
| `-t tagstring` | タグファイルを読み、指定タグの位置を開く |
| `-v` | `ex`として呼ばれてもvisualモードで開始 |
| `-V` | 端末以外からのコマンド入力をstderrへエコー |
| `-w size` | visualモードの編集ウィンドウサイズを指定 |

**環境変数**: `COLUMNS`(端末桁数上書き)、`EXINIT`(起動時実行コマンド、存在時は`.exrc`を無視)、
`HOME`(起動ファイルの場所)、`LANG`/`LC_ALL`(ロケール)、`LC_CTYPE`(バイト→文字マッピング・
正規表現の文字クラス)、`LC_MESSAGES`(メッセージ言語)、`LINES`(端末行数上書き)、`NLSPATH`、
`SHELL`(外部コマンド実行プログラム)、`TERM`(端末種別)。

**関連ファイル**: `/usr/libexec/expreserve`、`/usr/libexec/exrecover`、`/etc/termcap`、
`$HOME/.exrc`、`/var/tmp/Ex<番号>`(編集用一時ファイル)、`/var/tmp/Rx<番号>`(名前付きバッファ用
一時ファイル)、`/var/preserve`(保存領域)。

## 5. 正規表現・置換パターン(ex.1「Regular expressions」節より)

- `magic`モードの基本構文: 通常文字は自分自身にマッチ。`^`(行頭)、`$`(行末)、`.`(任意の1文字、
  改行以外)、`\<`/`\>`(単語境界)、`[string]`(文字クラス。`-`で範囲、`[:class:]`でPOSIX文字クラス、
  `^`で否定)、`\(...\)`(グルーピング)、`*`(0回以上の繰り返し)、`\{m,n\}`/`\{m\}`/`\{m,\}`
  (区間指定の繰り返し)、`~`(直前の置換テキストにマッチ)、`\n`(n番目のグループの後方参照)
- `nomagic`時はメタ文字が`^`/`$`のみに縮小し、他は`\`でエスケープしないとメタ文字として働かない
- 置換パターンのメタ文字: `&`(マッチ文字列全体)、`~`(直前の置換パターンの定義テキスト)、
  `#`(置換パターン全体が`#`の場合、直前の置換パターンを使う)、`\n`(n番目のグループの後方参照)、
  `\u`/`\l`(次の1文字を大文字/小文字化)、`\U`/`\L`...`\E`/`\e`(以降を大文字/小文字化)
- `LC_COLLATE`ロケールは無視される: `[.c.]`(照合要素)・`[=c=]`(等価クラス)は認識されるが`c`は
  単一文字に限定され実質的に無意味。範囲表現`[a-m]`は常にバイト順で評価される(TODO/NOTES共通の
  既知の制約、`docs/regex.md`の`stubs.c`分析と一致)

3. SVr4 exには、このポートにも実装すべき「暗黙の機能」がおそらく存在する(具体的内容は不明)

## 7. Changesに見る仕様上重要な変更点(コマンド挙動に影響するもののみ)

ビルド環境対応(コンパイラ/OS固有の修正)は除外し、コマンドの意味・挙動に関わる変更のみ抜粋。
Swift版で「意図的に再現する」または「意図的に再現しない」を判断する際の参考情報。

- **POSIX準拠のための挙動変更**(いずれも2002年前後、`POSIX_2`マクロのデフォルト化に伴うもの):
  - 正規表現ブラケット式内のバックスラッシュはデフォルトで特殊文字として扱われる(POSIX.2非準拠だが
    歴史的viの挙動・SVID互換・vim互換のため。`NO_BE_BACKSLASH`で POSIX準拠に戻せる)
  - `EXINIT`の処理は標準入力が端末かどうかに依存しない
  - visualモードで空ファイルに改行を追加しない
  - RE区間表現`\{m,n\}`・後方参照`\1`〜`\9`の追加
  - `-t tag`オプションと`wrapscan`オプションの競合を修正
  - `modelines`オプション名を`ml`に統一、`ex:`/`vi:`前の空白/タブを不要に
- **substituteコマンドの挙動**:
  - `substitute`は`sub`・`subst`等に省略可能になった(2005年)
  - `ignorecase`トグル時に保存済み正規表現も追従して更新されるよう修正(P = 移植時バグ修正)
  - 置換パターンが`%`単独の場合、直前置換のパターンを使う(POSIX準拠、SVR4互換)
- **ファイル操作の挙動**:
  - 存在しないファイル名を`edit`した場合、成功して`[New file]`と表示するよう修正
  - `next!`実行時、`autowrite`が設定されていてもカレントファイルを書き込まないよう修正
  - ファイルを開けない/無効アドレス/タグ未検出の場合、非0の終了ステータスを返すよう修正
  - `-t`と`-c`両方指定時は`-t`(タグ位置)を先に処理するよう修正
- **undo/マーク関連**:
  - `undo`操作で変更された行のマークが保持されるよう修正
  - visualモードの`X`が`x`と同じ動作をしてしまうバグを修正(本来の「カーソル前の文字を削除」に戻す)
- **マルチバイト対応(2004年以降に追加された新機能。バグではなく新規追加)**:
  - 伝統的正規表現がマルチバイト文字に対応
  - EUC-JP/Big5ロケールでの`r`コマンドの不具合修正、Big5ロケール対応
  - 複数カラム文字(全角文字等)の画面描画・undo・置換に関する多数の修正
- Swift版では、上記の「POSIXバグ修正で仕様が確定した挙動」(区間表現、後方参照、`%`置換等)は
  そのまま踏襲すべき仕様とみなし、「移植環境固有の修正」(P印のもの)はSwift版では前提が異なるため
  再現不要と判断してよい。マルチバイト関連の修正群は、Swift版の文字コード方針(内部`String`統一)
  により多くは構造的に発生しない問題だが、`docs/vi-mode.md`の画面描画ロジックとあわせて参照すること。
